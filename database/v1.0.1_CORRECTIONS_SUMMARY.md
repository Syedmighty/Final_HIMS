## Critical Issues Fixed

### 1. **Timestamp Trigger Syntax Error** (CRITICAL)

**Original Issue:**
```sql
-- ❌ BROKEN - This syntax doesn't exist in SQLite
SELECT datetime('now') INTO NEW.last_modified;
```

**Why It's Broken:**
- SQLite doesn't support `SELECT...INTO` in triggers
- SQLite doesn't support `SET` statements in triggers
- Using `UPDATE` inside `BEFORE UPDATE` trigger causes infinite recursion

**Fix Applied:**
```sql
-- ✅ CORRECTED - Triggers removed entirely
DROP TRIGGER IF EXISTS trg_products_update_timestamp;
DROP TRIGGER IF EXISTS trg_purchases_update_timestamp;
DROP TRIGGER IF EXISTS trg_issues_update_timestamp;

-- Application layer MUST now handle last_modified updates
```

**Impact:**
- **HIGH** - Original migration would **FAIL** with syntax error
- **CRITICAL** - Applications must be updated to set `last_modified` explicitly
- **BLOCKER** - Affects LAN sync functionality

**Documentation:** See `CRITICAL_TIMESTAMP_ISSUE.md` for full details and code examples.

### 2. **NULL Pointer Risks in Triggers**

**Original Issue:**
```sql
-- ❌ Could crash if NEW.modified_by is NULL
updated_by = NEW.modified_by
```

**Fix Applied:**
```sql
-- ✅ CORRECTED - COALESCE handles NULL safely
updated_by = COALESCE(NEW.modified_by, 'system')
```

**Applied to:**
- `trg_after_issue_approved`
- `trg_after_transfer_completed`
- All stock_adjustments inserts

---

### 3. **Missing NULL Checks for Foreign Keys**

**Original Issue:**
```sql
-- ❌ Could allow operations with NULL location_id
WHEN NEW.status = 'issued' AND OLD.status != 'issued'
```

**Fix Applied:**
```sql
-- ✅ CORRECTED - Validates FKs are not NULL
WHEN NEW.status = 'issued'
  AND OLD.status != 'issued'
  AND NEW.from_location_id IS NOT NULL
  AND NEW.to_location_id IS NOT NULL
```

**Applied to:**
- `trg_after_issue_approved`
- `trg_before_transfer_check_stock`
- `trg_after_transfer_completed`

---

### 4. **Double Stock Adjustment Risk**

**Original Issue:**
```sql
-- ❌ Could log duplicate adjustments if same product appears twice
SELECT product_uuid, SUM(quantity) ...
GROUP BY product_uuid
```

**Fix Applied:**
```sql
-- ✅ CORRECTED - HAVING clause prevents zero-quantity logs
SELECT product_uuid, SUM(quantity) ...
GROUP BY product_uuid
HAVING SUM(quantity) > 0  -- Only log if actual change occurred
```

**Applied to:**
- All `stock_adjustments` INSERT statements in issue/transfer triggers

---

### 5. **Performance Issues in EXISTS Queries**

**Original Issue:**
```sql
-- ❌ Scans entire result set even if match found
WHERE EXISTS (SELECT 1 FROM ... WHERE ...)
```

**Fix Applied:**
```sql
-- ✅ CORRECTED - Stops at first match
WHERE EXISTS (SELECT 1 FROM ... WHERE ... LIMIT 1)
```

**Applied to:**
- `trg_before_transfer_check_stock`
- `trg_after_stock_update_check_reorder`

---

### 6. **Schema Version History Corruption**

**Original Issue:**
```sql
-- ❌ Overwrites history, loses v1.0.0 record
UPDATE schema_migrations SET checksum = '...' WHERE version = '1.0.0';
```

**Fix Applied:**
```sql
-- ✅ CORRECTED - Preserves history
INSERT INTO schema_migrations (version, description, checksum)
VALUES ('1.0.1', 'Production hardening...', 'SHA256_v1.0.1_corrected');
```

---

### 7. **System User Duplicate Key Error**

**Original Issue:**
```sql
-- ❌ Fails if system user already exists
INSERT INTO users (...) VALUES ('system', ...);
```

**Fix Applied:**
```sql
-- ✅ CORRECTED - Idempotent insertion
INSERT INTO users (...)
SELECT 'system-user-000', 'system', ...
WHERE NOT EXISTS (SELECT 1 FROM users WHERE username='system' LIMIT 1);
```

---

### 8. **Verification Running Inside Transaction**

**Original Issue:**
```sql
BEGIN TRANSACTION;
  ... migration ...
  SELECT * FROM pragma_integrity_check;  -- ❌ Inside transaction
COMMIT;
```

**Fix Applied:**
```sql
BEGIN TRANSACTION;
  ... migration ...
COMMIT;

-- ✅ CORRECTED - Verification after COMMIT
SELECT * FROM pragma_integrity_check;
```

---

### 9. **Negative Quantity Handling**

**Original Issue:**
```sql
-- ❌ Would trigger alerts for negative stock (data error)
WHEN NEW.quantity IS NOT NULL
```

**Fix Applied:**
```sql
-- ✅ CORRECTED - Ignores invalid negative values
WHEN NEW.quantity IS NOT NULL
  AND NEW.quantity >= 0
```

**Applied to:**
- `trg_after_stock_update_check_reorder`

### Pre-Migration

- [ ] Backup database: `sqlite3 hims.db ".backup hims_backup.db"`
